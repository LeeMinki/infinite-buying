# 주문 미확정 복구와 체결 확인 개선

2026-09-07 구현. 세 전략과 운영 기록 분석은 PR #105에 별도로 정리했다. 이번 변경은 재현한 매수 정체·체결 오인·불완전 계좌 조회를 수정한다. 진입 필터, 예산, 손절률과 실주문 활성화 설정은 변경하지 않는다.

## 바뀐 동작

- 한국 랭킹의 주문번호 없는 `UNKNOWN`/`REQUESTED` 매수를 접수 완료로 표시하지 않는다. 발생일과 안전한 오류 코드를 표시하며 같은 스케줄러 오류 로그를 반복 적재하지 않는다. 전략은 `RUNNING`을 유지하되 주문 확인 전 신규 매수는 보류한다.
- 전략 응답 `orderAttention`은 최근 거래 페이지와 무관하게 가장 오래된 미확정 실주문을 사용자별로 반환한다. `REQUESTED`는 2분 이상 경과한 경우 표시한다. 화면은 미확정 주문을 보유 중 또는 손익 0%로 표시하지 않는다.
- 미국 랭킹은 증권사 주문번호와 확인된 양수 체결수량으로만 전략 보유를 인정한다. 계좌 잔고는 수량 상한으로 사용한다. 실제 평균체결가가 없으면 지정가나 계좌 평단으로 대체하지 않으며, 잔고 0만으로 청산과 손익을 확정하지 않는다.
- 시세·계좌·주문 요청은 서버 프로세스 내 같은 App Key의 공통 큐에서 최소 220ms 간격으로 실행한다. GET 재시도도 같은 큐를 사용하고 주문·취소 POST는 자동 재시도하지 않는다.
- 계좌·미체결·체결 이력은 연속조회가 끝나야 반환한다. 누락/반복 커서, 깨진 응답, 비정상 수량은 실패로 처리한다. 국내 주문 이력은 `ALL`과 최근 3개월 이전 TR 분할을 지원한다. 해외 미체결 조회는 공식 문서에 따라 `tr_cont` 대신 검색 키로 연속조회한다.

KIS 계약 기준: `KIS/한국투자증권_오픈API_전체문서_20260512_030000.xlsx`의 국내 잔고/정정취소가능/일별주문체결조회 및 해외 잔고/미체결/주문체결내역 API.

## 운영자 복구 절차

웹 API나 스케줄러에서 미확정 주문을 자동 해제하지 않는다. 서버 CLI는 다음 조건을 모두 만족하는 과거 주문만 처리한다.

1. 해당 사용자·전략의 국내 실매수, `UNKNOWN`, 원본 오류 `rt_cd=1`, `msg_cd=EGW00201`.
2. 증권사 주문번호와 체결 증거가 없고, 과거 거래일 `SELECTED` 미매수 진입이며 전략 보유가 없다. 다른 활성 주문이 없어야 한다.
3. 주문 당시와 현재 계좌가 같은지 운영자가 백업 등 독립 근거로 확인한다. 조회 중 계좌/인증정보 변경도 fingerprint 비교로 차단한다.
4. 같은 평가 잠금 아래 원래 거래일부터 현재까지 전 거래소 주문 내역, 전체 미체결, 해당 종목 잔고를 두 차례 새로 조회한다. 해당 종목의 취소/거부 내역을 포함해 한 건이라도 발견하면 중단한다.
5. 적용 직전 주문·진입·전략·계좌와 잠금을 재검증한다. 한 transaction으로 감사 행을 추가하고 주문 `FAILED`, 과거 진입 `SKIPPED`로 종결한다. 원본 오류/응답은 보존하며 증권사 `REJECTED`로 단정하지 않는다.

먼저 SQLite backup API로 일관된 비공개 백업을 생성한다. 아래 명령은 backend 컨테이너 `/app`에서 실행한다. 실제 ID와 조회 결과는 공개 PR에 올리지 않는다.

```sh
node src/operations/reconcileKrUnknownOrder.js --user-id USER_ID --order-id ORDER_ID
node src/operations/reconcileKrUnknownOrder.js --user-id USER_ID --order-id ORDER_ID --apply --acknowledge-no-broker-order --acknowledge-same-account
```

기본 명령은 상태를 변경하지 않는 미리보기다(조회 잠금은 잠시 사용한다). `--apply`도 미리보기 증거를 재사용하지 않고 전체 조회를 다시 수행한다. 주문·취소 API를 호출하지 않는다. 적용 후 `kr_order_reconciliations` 감사 행, 원주문 상태, 진입 상태, 전략 실행 상태와 다음 정상 평가를 확인한다. 조건 불충족 주문은 개별 조사하며 SQL로 강제 초기화하지 않는다.

## 배포와 검증

backend 배포는 `Recreate`로 변경해 이전 scheduler 종료 후 새 scheduler를 실행한다. 배포 중 짧은 API 중단이 발생할 수 있다. 마이그레이션 0038은 기존 매매 기록을 변경하지 않고 감사 테이블만 추가한다. 문제가 발생하면 이전 이미지로 롤백할 수 있으며 감사 테이블과 복구 근거는 보존한다.

`npm test`에 backend 회귀와 frontend SSR 검증을 포함한다. 복구의 미리보기, 적용 재조회, 사용자 격리, 같은 날 거절, 체결/잔고/미체결 발견 시 거절, 계좌 변경, 잠금·동시 상태 변경, 감사 기록 실패 시 원자성을 검증한다. 미국 체결 귀속/가격 지연, 공유 큐, 연속조회 실패도 mock API로 검증한다. 실제 주문으로 테스트하지 않는다.

수익성 개선은 별도 검증이 필요하다. 점심 후보 부족은 매수 필터의 결과일 수 있으므로 이번 복구 뒤에도 매수가 보장되지는 않는다. 여러 번 나눠 매도한 거래의 가중 손익과 과거 데이터 보정은 이번 변경에 포함하지 않는다.
