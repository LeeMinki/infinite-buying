# 미국 상승률 랭킹 전략 분석 — 2026-09-07

미국 전략은 매수 빈도나 손절 숫자를 조정하기 전에 **주문별 체결 증거, 정확한 손익 원장, 주문 복구**부터 보완해야 한다. 특히 주문번호 없는 `UNKNOWN` 매수 뒤 생긴 외부 잔고를 전략 체결로 오인하고 목표가 매도를 만드는 경로를 임시 DB와 모의 거래 서비스로 재현했다. 실제 운영에서 이 사고가 발생했다는 증거는 없지만, 재가동 전에 막아야 하는 코드 결함이다.

운영에 남은 미국 확정 왕복 거래는 두 건뿐이며 모두 현재의 5 USD 하한 도입 전 거래다. 이 두 건이나 휴장일 주문 실패 549건으로 최신 전략의 기대수익 또는 매수 필터의 성능을 판단할 수 없다.

## 재가동 전 우선 개선

### US-01 — UNKNOWN 매수와 외부 잔고의 소유권 오인

**확정된 코드 결함, 모의 재현 성공.** `capObservedBuyQuantity`는 `min(계좌 잔고, BUY 수량 상한)`을 반환한다. BUY 직전 잔고가 0이었다는 사실은 이후 사용자가 별도로 매수한 동일 종목까지 전략 소유로 만드는 증거가 아니다.

`evaluateEntryPath`는 이 수량이 양수이면 `UNKNOWN` 주문에도 보유 전환을 적용한다. 목표가 생성에 넘기는 객체는 `status: 'FILLED'`와 관찰 수량을 합성한다. 실제 BUY 행은 계속 `UNKNOWN`이어도 계좌 잔고와 미체결 목록 조건만 통과하면 SELL을 만들 수 있다.

모의 재현:

| 입력·관찰 | 결과 |
| --- | --- |
| 주문번호·확정 체결수량 없는 `UNKNOWN` BUY 5주 | 체결 동기화 후보 0건 |
| 현재 계좌에 외부 매수 5주, 해당 종목 미체결 목록 없음 | 전략 보유 5주로 전환 |
| 원래 BUY 상태 | 평가 후에도 `UNKNOWN` |
| 거래 서비스 모의 호출 | `TARGET` SELL 5주 1회 |

재현은 신규 임시 DB에 해당 날짜의 SELECTED 거래와 UNKNOWN BUY만 만든 뒤, `getBalance`를 5주·평단 50 USD, `getOpenOrders`를 빈 목록, `placeSellOrder`를 메모리 기록 함수로 교체하고 `evaluateStrategy`를 1회 호출했다. 날짜는 2026-09-08 ET 11:00으로 고정했다. 토큰 발급을 포함해 실제 fetch는 전혀 사용하지 않았다. 출력은 다음과 같다.

```json
{
  "mockedOnly": true,
  "syncCandidates": 0,
  "originalBuyStatus": "UNKNOWN",
  "holdingQuantity": 5,
  "sentViaMock": [{ "side": "SELL", "quantity": 5, "sellReason": "TARGET" }],
  "network": ["MOCK_TOKEN"]
}
```

근거: [매수 보유 전환](../../backend/src/services/usRankService.js#L1709), [체결 수량 상한](../../backend/src/services/usRankService.js#L2312), [목표가 생성](../../backend/src/services/usRankService.js#L1373).

개선: `UNKNOWN`·`REQUESTED`는 주문별 체결 또는 확정된 주문 identity 복구 전까지 계좌 잔고만으로 전략 포지션으로 전환하지 않는다. 잔고는 주문 원장으로 증명한 관리 수량의 상한으로만 쓴다. 체결 미확정 상태에서 외부 잔고를 관찰하면 별도 조정 상태를 기록한다. 인수 기준은 위 사례에서 실제 SELL 0건, 원주문 중복 BUY 0건이며, 진짜 부분체결 주문은 확인된 체결량만 보호하는 것이다.

### US-02 — 실제 체결가와 거래 요약을 분리하고 손익을 재계산

**운영 불일치 확인 + 현재 코드의 일반화 결함.** `finalizeSellClose`는 마지막 SELL의 가격을 trade 전체 매도가로 기록하고 `sumRealizedProfitUsd`는 전체 진입수량에 이 가격을 곱한다. 예를 들어 10주를 100에 사고 4주를 102, 6주를 95에 팔면 실제 손익은 -22인데 마지막 가격 95를 전체에 적용하면 -50이다. 미청산 상태에서 발생한 부분 매도의 실현손익도 CLOSED 거래 합계에는 아직 반영되지 않는다.

`updateFilledOrderFromRefresh`는 체결가는 없고 FILLED 상태만 확인된 경우 주문 지정가를 `averageFilledPrice`에 넣는다. 이후 `listFillSyncCandidates`는 체결수량·체결가가 양수인 FILLED를 제외하므로 추정가가 실제 체결가로 굳을 수 있다. 잔고 0 분기도 매도 체결 증거 없이 현재가로 trade를 닫는 경로가 남아 있다. 또한 `sumRealizedProfitUsd`는 주문의 live/dry 출처를 구분하지 않아 같은 전략에서 모의 거래와 실거래를 섞어 사용하면 모의 손익까지 누적 목표에 포함할 수 있다.

근거: [체결 확정](../../backend/src/services/usRankService.js#L1087), [체결가 폴백](../../backend/src/services/usRankService.js#L1261), [잔고 0 처리](../../backend/src/services/usRankService.js#L402), [실현손익 합계](../../backend/src/repositories/usRankRepository.js#L278), [동기화 후보](../../backend/src/repositories/usRankRepository.js#L411), [왕복 이력 조회](../../backend/src/repositories/usRankRepository.js#L444).

개선: 주문별 누적 체결량·금액과 실제/추정/미확정 출처, live/dry 실행 모드를 분리하고 모든 BUY·SELL 체결을 수량 가중 집계한다. 추정값은 `average_filled_price`에 쓰지 않는다. 체결가 미확정이면 손익도 미확정으로 남기고 재조회한다. 외부 매도·잔고 반영 지연·조회 누락은 확정 전략 매도로 계산하지 않는다. 과거 행은 원본을 보존한 보정 이력으로 재산출하고, 누적 목표 종료 역시 동일한 검증 원장을 사용한다. 인수 기준은 부분체결·재호가·취소 후 체결을 포함한 총수량·손익 일치와 위 두 거래의 -20.8085 USD 재현이다.

### US-03 — 시간·전략 실행 상태와 기존 주문의 관리를 분리

**코드로 확인된 관리 공백.** `evaluateStrategy`는 장 밖이면 체결 동기화 전에 반환하고, `evaluateUnlocked`는 보유 청산까지 같은 ET 10:00~16:00 gate를 적용한다. `listRunningStrategies`는 중지·삭제된 전략을 제외한다. 따라서 이전 거래일에서 넘어온 보유분은 다음 개장 09:30~10:00 동안 관리하지 않고, 사용자가 중지한 전략의 기존 주문도 정기 체결 관리 대상에서 빠진다.

반일장은 미지원이다. 기본 KST 04:30은 여름 ET 15:30, 겨울 ET 14:30으로, 13:00에 닫는 세션의 청산시각으로 사용할 수 없다. 코드의 “주문 거부만 발생하므로 잘못된 매매로 이어지지 않는다”는 주석은 기존 보유분의 미청산 위험을 설명하지 못한다. `forceCloseKst`는 00:00~11:59를 모두 허용하므로 정상 폐장 뒤 시각도 입력할 수 있다.

개선: 신규 진입 시간, 거래소 실제 주문 가능 시간, 기존 주문 조회 시간을 별도 정책으로 둔다. 거래소 캘린더에서 세션 종료시각을 결정하고 청산·진입 마감을 종료시각 이전으로 제한한다. 기존 live 주문·보유분은 전략 실행 여부와 독립적인 조정 작업이 조회한다. 중지 시 남은 포지션의 관리 정책을 화면에서 분명히 보여주며, 전역 kill switch의 쓰기 차단은 유지한다.

검증 시나리오: 반일장 13:00 폐장, DST 전환 전후, 전날 미체결의 09:30 이후 관리, 중지·삭제 직전/직후 부분체결. 로컬 시간 재현에서 2026-11-27 ET 14:00도 `isUsRegularSession=true`, 같은 날 ET 12:45 기본 강제청산은 false였다. 2026-09-07 노동절은 정상적으로 false였다.

### US-04 — 주문번호 없는 모호 상태의 복구와 유한한 실패 예산

**안전 차단은 구현됐지만 복구가 부족하다.** `listFillSyncCandidates`는 주문번호 없는 행을 제외하고, 취소는 번호가 없으면 실패한다. UNKNOWN을 안전하게 막는 기능만으로는 미접수가 나중에 확인돼도 전략이 자동으로 회복하지 못한다. 장기 차단을 단순히 FAILED로 바꾸거나 같은 주문을 재전송하면 안 된다.

또한 BUY 실패 5회 제한은 하루나 종목이 아니라 `trade_seq`가 포함된 멱등키 기준이다. 5회 뒤 사이클을 FAILED로 닫고 다음 평가에서 새 사이클을 만든다. 같은 오류·같은 종목이 계속 상위 후보면 다시 5회가 시작된다. 과거 휴장 실패는 현재 휴장일 판정으로 막혔지만, 다른 지속적인 업무 거절에서 회차를 바꾸며 반복하는 구조는 남아 있다.

근거: [동기화 대상](../../backend/src/repositories/usRankRepository.js#L411), [번호 없는 취소 차단](../../backend/src/services/usRankService.js#L1316), [매수 실패 한도 뒤 새 사이클](../../backend/src/services/usRankService.js#L1892).

개선: 모호 상태의 나이·마지막 조회·증거·필요 조치를 저장하는 복구 큐를 둔다. 계정 내 해당 기간의 주문·체결을 완전 조회해 증거가 유일한 경우에만 주문 identity를 연결하고, 모호하면 사용자의 계좌 확인을 위한 해결 절차를 제공한다. 별도로 오류 범위에 따라 계정·시장·종목·거래일 실패 예산과 대기 시간을 적용한다. 계좌 설정 오류에 종목만 바꿔 재시도하거나 영구 거절을 30초마다 반복하지 않아야 한다.

### US-05 — 연속조회와 호출 예산을 체결 안전의 일부로 처리

**코드상 첫 응답만 사용한다.** 해외 잔고·미체결·체결조회는 연속조회 키를 빈 값으로 보내고 첫 응답을 반환한다. 잔고 응답에서 종목이 없으면 0으로 변환하고, 미체결 응답에서는 종목 필터 후 빈 배열을 만들 수 있다. 데이터가 다음 페이지에 있는 경우 “없음”으로 오인하는 경로다. 실제 운영에서 페이지 누락이 발생했다는 증거는 없다. 정확한 연속조회 계약은 저장소의 KIS 공식 엑셀을 기준으로 구현해야 한다.

이미 `KisTradingService`에는 사용자별 호출 간격 제한과 GET 재시도가 있다. 추가 과제는 시세 계층까지 포함한 공유 예산·우선순위다. `KisMarketDataProvider`는 별도 fetch·재시도 경로이고, 미국 평가 전에 최대 20개 과거 주문 동기화를 직렬 수행한다. 분봉·랭킹·복기 조회가 보호 주문 조회·취소를 지연시키지 않는지 측정해야 한다. 30초는 설정 주기이며, 느린 응답 중에는 스케줄러가 다음 tick을 건너뛰므로 실제 방어 반응시간 보장이 아니다.

근거: [해외 잔고](../../backend/src/services/kisTradingService.js#L178), [미체결](../../backend/src/services/kisTradingService.js#L296), [체결 이력](../../backend/src/services/kisTradingService.js#L367), [공유 거래 호출 제한](../../backend/src/services/kisTradingService.js#L482), [시세 요청](../../backend/src/market-data/KisMarketDataProvider.js#L496), [동기화 반복](../../backend/src/services/usRankService.js#L2164).

개선: 페이지 끝 확인을 포함한 조회 완전성 상태를 반환하고, 불완전 응답은 잔고 0·미체결 없음으로 해석하지 않는다. 사용자별 전체 KIS 호출 예산에서 기존 포지션 조정·방어 주문을 우선하고 오래된 체결가 보정은 낮은 우선순위로 분리한다. 페이지 중단·중복 키·호출 제한·지연 조건에서 신규 주문 0건, 관리 포지션 보존을 검증한다. 구체적인 초당 한도는 실제 계정·API 계약을 확인한 뒤 정한다.

## 매수 기회와 전략 품질의 개선 가설

다음 항목은 개선 가능성이 있는 설계 가설이다. 현재 운영 표본으로 수익 개선을 확정하거나 한꺼번에 live 적용할 수 없다.

1. **미매수 원인을 보존한다.** 후보 없음·분봉 탈락·한 주도 못 사는 경우 SCHEDULED 평가는 `noLog`로 사유와 랭킹을 버린다. 스케줄러가 돌았다는 시각만으로는 시장에 후보가 없었는지 데이터가 실패했는지 모른다. 매 tick 원문 로그 대신 `reasonCode`, 후보 수, 필터별 탈락 수, 데이터 시각, 마지막 후보, 같은 사유의 발생 횟수와 시작·종료시각을 저장한다. 개인정보 없이 일별 진입 전환율과 데이터 장애 비율을 계산할 수 있어야 한다. 근거: [후보 선택](../../backend/src/services/usRankService.js#L1441), [후보 없음 기록](../../backend/src/services/usRankService.js#L1670), [noLog 처리](../../backend/src/services/usRankService.js#L2413).

2. **첫 주문과 지연된 SELECTED에도 신호 유효기간을 적용한다.** 현재 최신 랭킹·분봉·±2% 재확인은 명시 거절 이후 재시도에 집중된다. 아직 주문을 보내지 못한 SELECTED가 미체결·기존 잔고 등의 guard에 막혀 남으면 `failedAttempts=0`이므로 이후 같은 날 신호를 다시 확인하지 않고 첫 주문을 시도할 수 있다. 모든 신규 전송에 신호 생성시각·가격 변화·최신 후보 잔존을 검사하고, 만료되면 후보 선택부터 다시 시작한다.

3. **단일 종목 전액 진입 대신 전략 예산과 손실 예산을 둔다.** 현재 고정 금액 필드는 실사용되지 않는다. 주문 가능액, 전략에 배정한 금액, 거래당 손실 허용액/손절 거리, 유동성에 따른 상한 중 최소값으로 수량을 산정하는 안을 검증한다. 수수료·가격 변동 여유금도 반영한다. 목표 수익 2%·고정 손실 5%만 실현된다는 단순 가정에서 손익분기 승률은 비용 전 약 71.4%이지만, 실제로는 빠른 손절·시간 청산·부분체결이 섞이므로 관측 손익 분포로 다시 계산해야 한다.

4. **빠른 손절 이후 재진입 위험을 따로 측정한다.** 당일 잠금은 `STOP_LOSS`·`FORCE_CLOSE`에만 걸리고 `ENTRY_FAILED`에는 걸리지 않는다. 따라서 빠른 손절 직후 같은 급등주 재진입이 가능하다. 거래일 손실 예산, 같은 종목 대기 시간, 추세 재확인 중 어떤 조건이 반복 손실을 줄이는지 shadow로 비교한다. 무조건 하루 중지를 추가하면 정상적인 다음 기회도 사라질 수 있으므로 기록이 필요하다.

5. **분봉의 의미를 명확히 한다.** 최대 120개 분봉으로 계산한 값은 늦은 시간에는 최근 구간 VWAP이며 당일 전체 VWAP이 아니다. 시세 정규화는 날짜·신선도·완성 여부를 보존하지 않고, 진입 필터는 마지막 봉도 사용한다. 거래일, 관측시각, 완성봉 여부, 유효 거래량을 보존하고 “당일 VWAP”과 “최근 120분 VWAP”을 분리해 비교한다. 진행봉을 제외하는 정책도 신선도 기준과 함께 검증한다. 근거: [해외 분봉 조회](../../backend/src/market-data/KisMarketDataProvider.js#L145), [분봉 정규화](../../backend/src/market-data/KisMarketDataProvider.js#L719).

6. **빠른 손절 명세와 호출을 맞춘다.** 공통 `evaluateFastStopLoss`는 `holdingMinutes`가 있을 때만 20분 한도를 적용하지만 미국 호출은 그 값을 전달하지 않는다. 현재 명세의 “매수 후 20분이 지나면 미적용”과 구현이 다르다. 실제 매수 체결시각을 사용할지, 제한 없이 구조적 손절을 유지할지 명시적으로 결정하고 양쪽 경계 테스트를 둔다. 근거: [미국 빠른 손절 호출](../../backend/src/services/usRankService.js#L524), [공통 빠른 손절](../../backend/src/services/krRankStrategyEngine.js#L705).

7. **호가 기반 실행 비용을 측정한다.** 현재 매수는 현재가 지정가, 재호가 매도는 현재가 대비 할인율을 사용한다. 진입 당시 스프레드·매수호가 잔량·주문 크기·체결 지연을 수집해 실제 체결 비용과 미체결률을 비교한다. “공격적 지정가가 체결을 보장한다”는 표현은 제거해야 한다. 거래정지·호가 소멸 상황에서는 충분히 낮은 지정가도 체결을 보장하지 않는다.

## 검증 결과와 후속 완료 기준

실행한 기존 테스트:

```bash
node --test backend/tests/usRankStrategy.test.js backend/tests/usRankService.test.js backend/tests/usRankFillSync.test.js
```

결과: **70개 통과, 0개 실패**, 약 41.3초. 기존 테스트는 접수/체결 분리, 부분체결·취소 경합, 외부 수량 상한, 전역 차단, 과거 주문 조회 등을 검증한다. 70개 통과는 위에서 식별한 새로운 시나리오나 실계좌 수익성까지 검증했다는 뜻이 아니다.

추가로 임시 DB와 전면 모의 거래 계층에서 US-01을 재현했다. 네트워크는 mock token 응답으로 대체했고 SELL은 메모리 배열에만 기록했다. 반일장·개장 전후 판정은 순수 엔진 호출로 확인했다. 영구 테스트 파일이나 알고리즘 코드는 변경하지 않았다.

권장 후속 순서:

1. UNKNOWN/외부 잔고 오인 차단과 체결·손익 원장 정합성을 먼저 수정한다. 누적 수익 종료는 검증된 체결 원장에만 의존하게 한다.
2. 기존 주문의 복구, 중지 상태 조정, 반일장 캘린더, 완전한 조회와 방어 주문 우선 호출을 검증한다.
3. 무주문 사유와 버전별 신호·체결 비용을 수집한다. 최신 규칙의 실제 후보와 신호 시점 데이터를 저장해야 비교가 가능하다.
4. 사전에 정한 서로 다른 거래일·종목 표본으로 대조안을 shadow 평가한다. 선택된 후보만 복기하지 말고 탈락 후보도 포함해 비용 차감 후 기대손익, 최대 낙폭, 회전율, 미체결률, 주문 오류율을 비교한다. 표본이 부족하거나 신뢰구간이 넓으면 수익 개선을 확정하지 않는다.

이번 분석만으로 미국 전략을 자동 재시작하거나 과열·유동성 필터를 완화할 근거는 없다. 현재 미국 무주문은 중지 상태와 최신 운영 표본 부재부터 설명해야 하고, 장기적인 개선은 “주문이 나갔는가”와 “올바른 포지션을 비용 후 이익으로 관리했는가”를 함께 검증해야 한다.
