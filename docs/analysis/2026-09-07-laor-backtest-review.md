## 판단

라오어는 현재 실주문 안전 잠금과 중지 상태가 있으므로, 매수 빈도를 높이기 위해 잠금을 해제할 단계가 아니다. 과거 주문 네 건만으로 수익성을 평가할 수도 없다. 먼저 체결 원장과 전략 귀속 자산을 확정한 뒤, 수동 계산·일봉 백테스트·실전 엔진 사이의 수량 및 주문 시점 차이를 없애야 한다.

백테스트 39회의 좋은 결과는 독립된 실전 검증 39회가 아니다. 같은 레버리지 ETF와 겹치는 기간을 반복 계산한 자료이며, 수수료·세금·슬리피지 없이 일봉에서 지정가가 체결된다고 가정한다. 랭킹 거래 복기와 최근 구간 재현 역시 유용한 진단 도구지만, 신규 진입 규칙의 실주문 승격을 판정할 완성된 검증기는 아직 아니다.

검증 조건: 접수 후 응답 유실·재시작에도 POST 중복 0건, 부분체결 누적 반영 한 번, 미체결 매도에서 회차·보유 유지, 외부 동일종목 수량 매도 0주, 전략 예약금 합계가 배정 현금을 넘지 않음. DRY_RUN 기록은 실제 운용 회차·예약금·당일 주문 슬롯을 소모하지 않는 별도 상태로 분리한다.

### P1: 실현손익은 확인된 체결 수량으로만 계산

`buildLaorRealizedRecords`는 FAILED/REJECTED/CANCELED/DRY_RUN만 제외하고, `orderQuantity()`가 `filledQuantity || quantity`를 사용한다(`autoTradingService.js:587`, `:731`). 체결량 0이면 주문 수량으로 대체되어 UNKNOWN·ACCEPTED도 실현손익이 된다. 반대로 일부 체결 뒤 취소한 주문을 CANCELED라는 이유로 통째로 빼면 실제 체결이 사라진다.

로컬 재현: 가상의 UNKNOWN 매수 1주·100달러와 ACCEPTED 매도 1주·110달러를 넣고 두 주문 모두 `filledQuantity=0`으로 설정했는데, 실현손익 +10달러 한 건이 반환됐다. 실제 운영 라오어 기록에는 매도가 없어 이 재현만으로 현재 계좌의 실현손익이 잘못 표시됐다고 단정하지 않는다.

개선: 주문 상태와 별개로 확인된 누적 체결 수량·금액을 원장에 반영하고 부분취소도 이미 체결된 부분은 보존한다. 주문 생성일 대신 실제 체결일로 기간을 나눈다. 체결 증거가 없는 금액은 0원으로 추정하지 않고 미확인으로 표시한다.

### P1: 처음 한 주 매수 가능과 후속 분할매수 가능을 구분

첫 회차는 `cycleBudget / splitCount`, 이후 각 슬롯은 그 절반이다. 라이브는 현재가가 더 싸더라도 수량을 AVG/BIG 지정가 기준으로 계산한다. 예산 1,000달러·40분할·25달러 종목은 첫 한 주를 살 수 있지만 다음 회차의 슬롯 예산은 12.5달러라 AVG/BIG 모두 0주다. 로컬 실행에서 다음 현재가가 25달러일 때와 10달러일 때 모두 HOLD였다.

`computeMaxSplitCount()`의 계산 보조 함수는 있으나 현재 호출부가 없고 큰수 지정가의 추가 여유율까지 반영하지 않는다. 설정 화면에 첫 매수 가능 수량과 후속 AVG/BIG 수량을 각각 보여주고, 둘 다 0주인 설정을 저장·시작할 때 이유를 알려야 한다. 자동으로 분할 회차나 예산을 바꾸지는 않는다. 예산·분할을 사용자가 조정한 뒤 같은 입력으로 미리보기와 실행 결과가 일치하는지 검증한다.

### P1: 장 운영 시간과 최종 차단 사유

라오어의 `isMarketSessionOpen()`은 한국 요일로 주말을 제외하고 미국 시간을 한국시간 22:30~06:00으로 고정한다(`autoTradingService.js:1237`). 미국 금요일 오후는 한국 토요일이므로 평가가 누락되고, DST 여부에 따라 장전·장후가 포함된다. 미국 랭킹에서 쓰는 뉴욕 현지 시간 원칙에 맞춰 시장별 공통 세션 판정을 적용하고 휴장·조기종료도 다뤄야 한다. UTC 거래일 사용 자체는 미국 정규장 중간에 날짜가 바뀌는 문제와는 다르다.

또한 매수 판단 로그를 먼저 저장한 뒤 안전 검증 실패 시 `continue`만 한다(`autoTradingService.js:267`, `:299`). 사용자는 BUY 판단만 보고 주문이 왜 없는지 알기 어렵다. 미체결 차단·현금 부족·중복 슬롯·재시도 소진을 최종 실행 결과로 기록하고, 최초 판단과 마지막 차단 사유를 같이 보여주는 것이 매수 필터 완화보다 먼저다.

## 4. 백테스트의 실전 적합성

### P1: 주문 수량과 관찰 시점을 공유

현재 백테스트는 더 좋은 체결가를 안 뒤 수량을 정한다. 실제 지정가 주문은 주문 수량을 먼저 정하고 체결가가 개선되어도 주식 수가 저절로 늘지 않는다.

로컬 재현 입력은 사이클 예산 4,000달러, 40분할, 평단 40달러, 보유 10주, 현금 2,000달러, 시가·현재가 25달러다. 목표매도가 발생하지 않도록 일봉 고가 41·저가 24·종가 30을 사용했다.

| 결과 | AVG | BIG | 합계 |
| --- | --- | --- | ---: |
| 라이브 엔진 | 40달러 지정가 1주 | 44달러 지정가 1주 | 2주 |
| 일봉 엔진 | 25달러 체결 2주 | 25달러 체결 2주 | 4주 |

수동 계산기는 또 충족한 절반 예산을 합친 뒤 정수화한다. 따라서 동일 설정이라는 UI 문구만으로 세 경로가 같은 전략은 아니다. 공통 순수 함수에서 주문 의도·수량·회차 전이를 만들고, 실행 어댑터가 시세 관찰과 체결만 처리하도록 정리하는 것이 우선이다. 슬롯별 정수 잔액, 갭 하락, 회차 소진, 매도 후 재시작을 공통 fixture로 대조해야 한다.

라이브는 가격이 닿았던 10분 사이 순간을 놓칠 수 있지만 일봉은 그날 저가·고가를 모두 이용한다. 전일 정보로 주문을 미리 걸어둔 모형과 10분마다 보고 주문하는 모형을 구분하고, 후자를 재현하려면 당시 시세·평가 시각·주문 지연이 필요하다.

### P1: 동일봉 순서와 비용을 성과에 반영

- 목표 고가가 닿는 날은 추가 매수를 전부 생략한다(`strategyEngine.js:223`). 같은 날 먼저 저가에서 매수된 뒤 목표가가 도달했을 수도 있다. 일봉만으로 이를 확정할 수 없으므로 시나리오별 결과와 모호한 날짜 수를 반환해야 한다. 편향 방향은 상황마다 다르다.
- 첫 매수 당일에는 이후 목표가 도달을 평가하지 않는다(`strategyEngine.js:265`). 장중 재평가가 있는 실전과 다르다.
- 수수료·세금·거래소 비용·환전비용·슬리피지·유동성 제한은 없다. 전부 필수로 일률 부과할 것이 아니라 시장·거래유형·통화별 실제 발생 비용을 설정으로 남겨야 한다. USD 자체 수익과 원화 환산 수익도 분리한다.
- MDD는 각 결정 이후 잔고를 그날 종가로 평가해 갱신한다(`BacktestExecutionProvider.js:45`). 장중 저점이나 미체결 청산 지연의 손실을 포함하지 않으며, 같은 날짜의 여러 중간 보유 상태도 들어간다. 일별 최종 자산 MDD와 장중/체결 지연 스트레스 MDD를 따로 정의한다.
- SOXL/TQQQ에 대해서는 동일 기간 매수 후 보유·현금·단순 정액매수와 비용 후 성과를 비교하고, 횡보·급락·회복 구간의 최대 낙폭·회복기간·자금고갈 횟수를 제시한다. 레버리지 ETF 두 종목의 특정 구간 고수익만으로 일반화하지 않는다.

### P1: 결과를 계산한 코드·데이터·정책 버전 보존

현재 run에는 알고리즘 문자열과 일부 파라미터가 있지만 실행 commit, 데이터 해시, 비용·체결 모델 버전이 없다. `effectiveBigBuyPremiumRate`도 조회 때 현재 `resolveBigBuyPremiumRate()`로 다시 계산한다(`backtestRunsRepository.js:23`). 과거 기본 정책이 달랐다면 예전 결과의 설명이 현재 정책으로 바뀔 수 있다.

Git 이력에서 `632ba66`은 NATIVE 전환·소수점 옵션, `73bc10f`는 큰수 기준을 평단가로 변경, `bf67365`는 이월 제거·회차 모델 정렬을 담고 있다. 같은 NATIVE 문자열만으로 세부 알고리즘이 같다고 보장할 수 없다. 과거 문서의 carryover 설명과 현재 구현도 다르다.

개선: 실행 시점의 해석 완료 파라미터, 전략 코드 버전, 체결·비용 모델, 원천 OHLC 범위·누락·수정 여부와 해시를 저장한다. 기존 run을 새 의미로 덮어쓰지 않고 보관하며, 같은 입력을 현재 엔진으로 다시 계산한 결과를 별도 run으로 비교한다. 중복·겹치는 요청은 표본 수에서 구분한다.

## 5. 랭킹 거래 복기·최근 재현의 한계

`rankReplayService`는 목표·손절 동일 분봉의 선후 불확실성을 이미 표시하고, 실거래 한 건의 분석이라는 안내도 제공한다. `backtestKrRankRecent`는 완성봉만 진입 판단에 사용하며 비용·불리한 매수 캡·동일봉 손절 우선 시나리오를 이미 갖고 있다. 이를 신규 개선처럼 다시 제안할 필요는 없다.

| 추가 개선 | 근거와 검증 조건 |
| --- | --- |
| 복기 분봉 범위 완전성 | 복기는 매수 +100분을 기준으로 약 120봉 한 번을 조회한다(`rankReplayService.js:24`, `:58`). 오래 보유하거나 여러 날에 걸친 거래는 일부만 분석될 수 있다. 매수~실제 매도 전체 페이지를 수집하거나 `coverageComplete=false`, 분석 종료 시각, 누락 구간을 반환해야 함 |
| 실제 체결 시각 적용 | US 왕복 조회는 주문 `created_at`을 buy/sell 시각으로 우선 사용한다(`usRankRepository.js:467`, `:476`). 미체결 대기 구간의 가격을 보유 손익에 넣지 않도록 실제 체결 시각·부분체결 구간으로 정렬해야 함 |
| 빠른 손절 시간창 일치 | `firstFastStopLoss()`는 30봉 창은 사용하지만 `holdingMinutes`를 전달하지 않는다(`rankReplayService.js:147`). 엔진의 최대 보유시간 조건(`krRankStrategyEngine.js:705`)이 빠져 오래된 거래도 초기 실패로 판정할 수 있음. 매수 전 창·완성봉·보유시간을 라이브와 대조해야 함 |
| 복기 검색 상한 | 거래를 사용자·전략 범위 내 최근 500건에서 찾는다(`rankReplayService.js:11`). 더 오래된 거래는 존재해도 못 찾는다. 범위를 지킨 단건 조회로 바꾸고 대량 전체 감사에는 pagination 사용 |
| 합성 랭킹의 표본 한계 | 최근 재현은 최신 12개 실제 top10에 있었던 종목만 재구성한다(`backtestKrRankRecent.js:63`, `:444`). 이후 새로 들어온 종목과 실제 30초 순위를 알 수 없으며 고정한 10위 하한도 이후 실제 시장 순위는 아님. 합성 결과는 근사 등급으로 표시하고 실제 관찰과 구분 |
| 현재 라이브 재탐색과 재현 코드 일치 | 스크립트의 다음 tick 확인 실패는 즉시 해당 구간을 종료한다(`backtestKrRankRecent.js:278`). 최근 live 재시도·fallback 정책의 비교에 그대로 쓰면 정책 차이가 섞인다. 시점별 policy version과 공통 실행 규칙이 필요 |
| 진입 분과 청산 창 | `simulateExit()`는 진입 분 전체를 제외하고 이후 관찰봉만 초기화한다(`backtestKrRankRecent.js:595`). 미래 데이터 사용을 피하지만 진입 직후 급락은 누락될 수 있고 매수 전 30봉도 빠진다. 진입 분은 불확실 처리하고 체결 후 최초 가능한 관찰부터 보수적으로 평가 |
| 손절 갭·데이터 결측 | 비용 시나리오도 손절가는 `min(stop, close)`다(`backtestKrRankRecent.js:661`). 장중 갭·호가·체결 대기를 완전히 재현하지 못한다. 청산 데이터가 없으면 해당 거래를 `skipped` 처리하므로 결측 종목의 열린 위험을 성과에서 제외하지 않도록 별도 미해결 집계 필요 |
| 자본과 MDD | 시작 자본은 실행 당시 매수가능금액 입력이고 MDD는 종료 거래 기준 자본 곡선이다. 역사적 실제 계좌 수익률 또는 장중 MDD로 표시하지 말고, 고정 배정자본·일별 평가자산·예약금·비용 기준을 명시 |

복기 대상은 원래 선택된 거래들이므로, 이들만으로 진입 필터를 최적화하면 선택되지 않은 후보와 무거래 구간이 빠진다. 원래 매도 시각에서 분석을 끊은 목표율 비교도 더 오래 보유한 대안의 결과를 보여주지 못한다. 실제 거래 진단과 대안 정책 실험의 데이터 범위를 따로 정의해야 한다.

## 6. 수익성 승격 조건과 작업 순서

기존 [시간분할 검증](../../kr-rank-timesplit-validation-2026-08-20.md)은 과거 실제 매수 75건 및 최근 관찰 구간의 변형에서 표본이 충분하면서 TRAIN/VALIDATION 모두 양수·PF>1인 규칙이 없다고 보고했다. [최근 재현 보고서](../../kr-rank-current-backtest-2026-08-19.md)도 저장 시각 엄격 재현에서 매수 0건이며 합성 재탐색 후보도 손실 또는 미진입이라고 결론 냈다. 이번 문서는 당시 분봉 API를 재호출해 독립 재현한 결과가 아니라, 기존 증거와 현재 코드·새 전체 기록 집계를 교차 검토한 결과다.

현재 [구현 작업 목록](../../specs/007-improve-trading-retries/tasks.md)의 T003(결정적 fixture), T013~T016(실험·가상체결·성과·승격 판정)은 미완료로 남아 있다. raw top30 shadow 저장은 이미 일부 구현되어 있으나 완성된 가상 포트폴리오·검증 판정까지 구현된 것은 아니다. 문서의 합격 기준은 최소 validation 20거래, 비용 후 기대값>0, PF>1, MDD≤10%의 논리곱이다. 20건은 통계적 수익성 보장을 뜻하지 않는다.

권장 순서는 다음과 같다.

1. **체결과 기록 정확성**: 라오어 잠금 유지, UNKNOWN 복구·체결 수량 기반 손익·전략 소유 원장·실행 차단 사유를 정리한다.
2. **실전과 재현 정렬**: 세 라오어 계산 경로의 주문 수량·회차 규칙을 정리하고 비용·동일봉 순서·데이터 결측을 fixture로 검증한다. 과거 39회는 원본을 보존한 채 재계산한다.
3. **관찰 증거 확보**: 실제 시각별 순위·후보·필터 결과·시세·완성봉·주문 지연을 policy version과 함께 저장한다. 무거래 구간도 분모에 포함한다.
4. **후보 실험**: 진입 조건을 하나씩 변경하고 연대순 TRAIN/VALIDATION/최종 미사용 TEST를 분리한다. 인접한 분봉을 무작위로 나누지 않고, 같은 날짜·종목 중복과 탐색한 변형 수를 기록한다.
5. **승격 판정 자동화**: 기존 최소 기준에 기간별 안정성·비용 스트레스·낙폭 회복·불확실 거래 비율을 함께 보고한다. 새 규칙은 독립 검증 후 검토하며, raw 관찰이 늘었다는 사실만으로 실주문을 자동 활성화하지 않는다.

핵심 검증 산출물은 실행 가능한 공통 fixture, 코드·데이터 해시가 남는 결과 파일, 비용 후 자산곡선, 미확인·누락 구간 목록, 주문 중복·외부 물량 매도 0건의 증거다. 단순히 주문 건수나 과거 최고 수익률이 증가한 결과를 완료 조건으로 삼지 않는다.

## 7. 이번 분석의 검증

공통 검증에서 backend 전체 테스트 327/327과 frontend production build가 통과했다. 추가로 이 문서의 가상 입력을 이용해 백테스트·라이브 수량 차이, 첫 매수 뒤 후속 슬롯 0주, 미확인 주문의 가상 실현손익 세 사례를 로컬에서 직접 실행해 확인했다. 기존 테스트 통과는 이 세 문제나 실전 수익성이 검증됐다는 뜻이 아니다. 해당 경계 사례를 고정 fixture로 추가하는 일은 위 개선 구현의 완료 조건이며, 이번 분석 PR에는 실거래 코드 변경을 포함하지 않는다.
