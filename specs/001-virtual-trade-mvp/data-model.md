# Data Model: Infinite Buying Strategy Assistant MVP

## Entity: Strategy

Represents one virtual strategy for one stock.

Fields:

- `id`: integer primary key
- `name`: required display name
- `stock_code`: required stock identifier
- `stock_name`: required stock display name
- `total_budget`: required positive integer
- `split_count`: required positive integer, default `40`
- `buy_amount_per_round`: required integer, calculated as `floor(total_budget / split_count)`
- `target_profit_rate`: required positive decimal, default `0.10`
- `current_round`: required positive integer, default `1`
- `status`: `ACTIVE` or `PAUSED`
- `created_at`: creation timestamp
- `updated_at`: last update timestamp

Relationships:

- has one `Holding`
- has many `VirtualOrder`
- has many `DecisionLog`

Validation:

- total budget must be greater than zero
- split count must be greater than zero
- current round must be between `1` and `split_count + 1`
- status must be `ACTIVE` or `PAUSED`

## Entity: Holding

Represents virtual position state for one strategy.

Fields:

- `id`: integer primary key
- `strategy_id`: required unique reference to `Strategy`
- `quantity`: non-negative integer
- `average_price`: non-negative decimal
- `invested_amount`: non-negative integer
- `remaining_budget`: non-negative integer
- `realized_profit`: integer, can be negative
- `updated_at`: last update timestamp

Relationships:

- belongs to one `Strategy`

Validation:

- one holding row exists for every strategy
- remaining budget starts as strategy total budget
- average price is zero when quantity is zero

## Entity: VirtualOrder

Represents a simulated order generated by evaluation.

Fields:

- `id`: integer primary key
- `strategy_id`: required reference to `Strategy`
- `order_date`: calendar date used for duplicate BUY prevention
- `side`: `BUY` or `SELL`
- `price`: positive decimal
- `quantity`: positive integer
- `amount`: positive integer
- `status`: `PENDING`, `FILLED`, or `CANCELED`
- `round_no`: positive integer strategy round
- `reason`: required decision explanation
- `created_at`: creation timestamp
- `filled_at`: fill timestamp, null unless filled

Relationships:

- belongs to one `Strategy`

State transitions:

- `PENDING -> FILLED`
- `PENDING -> CANCELED`
- `FILLED` and `CANCELED` are terminal states

Validation:

- only pending orders can be filled or canceled
- BUY duplicate key: same strategy, order date, and round number must not repeat
- all orders are virtual; no broker order id is stored

## Entity: DecisionLog

Represents an audit record for one evaluation attempt.

Fields:

- `id`: integer primary key
- `strategy_id`: required reference to `Strategy`
- `input_price`: positive decimal
- `average_price`: non-negative decimal at evaluation time
- `quantity`: non-negative holding quantity at evaluation time
- `decision`: `BUY`, `SELL`, `HOLD`, or `PAUSE`
- `reason`: required explanation
- `created_at`: creation timestamp

Relationships:

- belongs to one `Strategy`

Validation:

- a log is written for every evaluation attempt, including HOLD and PAUSE

## Entity: MarketPriceCache

Represents daily stock price data used by the chart.

Fields:

- `id`: integer primary key
- `stock_code`: required stock identifier
- `date`: required market date
- `open`: required decimal
- `high`: required decimal
- `low`: required decimal
- `close`: required decimal
- `volume`: non-negative integer
- `created_at`: creation timestamp

Validation:

- one row per stock code and date
- high should be greater than or equal to open, low, and close
- low should be less than or equal to open, high, and close

## Holding Update Rules

Virtual BUY fill:

- new quantity = old quantity + order quantity
- new invested amount = old invested amount + order amount
- new average price = new invested amount / new quantity
- new remaining budget = old remaining budget - order amount
- strategy current round increments by one after successful fill

Virtual SELL fill:

- sell quantity must not exceed current holding quantity
- realized profit increases by `(sell price - average price) * sell quantity`
- remaining budget increases by order amount
- quantity decreases by order quantity
- if quantity becomes zero, average price and invested amount become zero
- if quantity remains, invested amount becomes `average_price * remaining quantity`

Virtual cancel:

- order status changes to `CANCELED`
- holding values do not change
