## Requirements
### Requirement: 자동매매 도메인은 복수 전략 종류를 독립 운용한다

자동매매 도메인은 라오어 무한매수법 전략(`LAOR_INFINITE_V2`), 한국 국장 상승률 랭킹 전략(`KR_RANK_MOMENTUM`), 미국장 상승률 랭킹 전략(`US_RANK_MOMENTUM`)을 서로 독립된 전략 종류로 함께 운용해야 한다(MUST). 세 전략 종류는 각자의 테이블·엔진·평가 경로를 가지며, 한 종류의 추가·평가·상태 변경·삭제가 다른 종류의 알고리즘·기록·상태에 영향을 주어서는 안 된다.

실주문 실행 설정(`user_trading_settings.live_order_enabled`, 사용자당 1행), KIS 토큰·잔고·주문 연동(`kisAuthService`/`kisTradingService`), 동시 평가 락·멱등키 패턴은 세 전략 종류가 공유한다. 스케줄러 모듈(`autoTradingScheduler`)은 라오어용 타이머(기본 10분), 한국 랭킹용 타이머(기본 30초), 미국 랭킹용 타이머(기본 30초)를 각자 다른 평가 경로로 운용하며, 세 타이머는 독립 동작해야 한다. 라오어 전략의 평가 사이클·상태 머신·기록은 본 요구사항으로 변경되지 않는다.

#### Scenario: 세 전략 종류를 각자의 주기로 평가
- **WHEN** 스케줄러 모듈이 동작 중
- **THEN** RUNNING 상태의 라오어 전략, 한국 랭킹 전략, 미국 랭킹 전략이 각자의 타이머 주기와 엔진으로 평가되어야 한다
- **AND** 한 종류의 평가 실패가 다른 종류의 평가를 막지 않아야 한다

#### Scenario: 실주문 설정 공유
- **WHEN** 사용자가 실주문 실행 설정을 변경
- **THEN** 라오어 전략, 한국 랭킹 전략, 미국 랭킹 전략 모두 같은 설정 값을 따라야 한다

#### Scenario: 라오어 전략 동작 불변
- **WHEN** 한국 랭킹 전략 또는 미국 랭킹 전략이 추가되어 운용됨
- **THEN** 라오어 전략의 회차·이월 예산·사이클 예산·판단 로그 동작은 종전과 동일해야 한다

### Requirement: 랭킹 전략 삭제 시 매매 이력을 보존한다

시스템은 한국 국장 상승률 랭킹 전략과 미국장 상승률 랭킹 전략을 삭제할 때 전략 행을 실행 대상과 기본 목록에서 제외하되, 해당 전략의 주문 이력·판단 로그·진입 기록·매매 사이클 데이터는 보존해야 한다(MUST). 삭제는 soft delete(`deleted_at` 기록)로 처리하며, 삭제된 전략은 스케줄러 평가 대상이 아니어야 하고 신규 평가·주문을 만들 수 없어야 한다. 사용자별 데이터 격리는 유지되어야 한다.

#### Scenario: 한국 랭킹 전략 삭제 후 이력 보존
- **WHEN** 사용자가 한국 국장 상승률 랭킹 전략을 삭제
- **THEN** 해당 전략은 기본 전략 목록과 스케줄러 평가 대상에서 제외되어야 한다
- **AND** 기존 주문 이력과 판단 로그는 DB에서 삭제되지 않아야 한다

#### Scenario: 미국 랭킹 전략 삭제 후 이력 보존
- **WHEN** 사용자가 미국장 상승률 랭킹 전략을 삭제
- **THEN** 해당 전략은 기본 전략 목록과 스케줄러 평가 대상에서 제외되어야 한다
- **AND** 기존 주문 이력과 판단 로그와 매매 사이클은 DB에서 삭제되지 않아야 한다

#### Scenario: 다른 사용자의 삭제 전략 접근 차단
- **WHEN** 사용자가 다른 사용자의 삭제된 전략 id로 기록 API를 호출
- **THEN** 시스템은 해당 기록을 반환하지 않아야 한다

### Requirement: 랭킹 전략 주문 충돌 안전장치

자동매매 시스템은 한국장·미국장 랭킹 전략에서 동일 보유분 또는 동일 매매 사이클에 대해 목표가 매도 주문과 손절·빠른 손절·강제 청산 매도 주문이 동시에 열리지 않도록 보장해야 한다(MUST). 접수된 주문은 체결 확인 전까지 체결로 간주해서는 안 된다(MUST).

#### Scenario: 목표가 주문 접수 상태

- **WHEN** 목표가 매도 주문이 `ACCEPTED` 상태이나 체결 수량이 확인되지 않음
- **THEN** 시스템은 보유 상태를 청산 완료로 바꾸지 않아야 한다

#### Scenario: 방어 매도 전 미체결 목표가 확인

- **WHEN** 방어 매도 조건이 발생하고 같은 보유분에 미체결 목표가 주문이 있음
- **THEN** 시스템은 목표가 주문 상태를 확인하거나 취소를 시도해야 한다
- **AND** 주문 충돌 위험이 있으면 신규 매도를 보내지 않아야 한다

### Requirement: 자동매매 화면 거래 복기 진입점

자동매매 화면은 한국장·미국장 랭킹 전략 주문 이력에서 거래 복기 기능으로 진입할 수 있어야 한다(MUST). 복기 기능은 백테스트와 구분되는 용어로 표시되어야 하며, 사용자가 명시적으로 실행할 때만 KIS 과거 분봉을 조회해야 한다(MUST).

#### Scenario: 주문 이력에서 복기 실행

- **WHEN** 사용자가 한국장 또는 미국장 랭킹 전략 주문 이력의 완료된 왕복 거래에서 복기 버튼을 누름
- **THEN** 시스템은 해당 거래의 분봉 복기 결과를 표시해야 한다

#### Scenario: 화면 진입 시 자동 호출 금지

- **WHEN** 사용자가 자동매매 화면을 열거나 탭을 전환
- **THEN** 시스템은 거래 복기용 과거 분봉 API를 자동 호출하지 않아야 한다

### Requirement: 랭킹 전략 결과 사유 구분

자동매매 시스템은 한국장·미국장 랭킹 전략의 매도 사유를 목표 수익, 손절, 빠른 손절, 청산 시각, 누적 목표 종료로 구분해 저장하고 화면에 표시해야 한다(MUST).

#### Scenario: 빠른 손절 매도 표시

- **WHEN** 보유 종목이 빠른 손절 조건으로 매도됨
- **THEN** 주문 이력과 판단 로그에는 "빠른 손절" 사유가 표시되어야 한다

#### Scenario: 목표 수익 주문 체결 표시

- **WHEN** 미리 제출된 목표가 주문이 체결됨
- **THEN** 주문 이력에는 매도 사유가 "목표 수익"으로 표시되어야 한다
