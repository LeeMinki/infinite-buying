## Context

`LAOR_INFINITE_V2`(native: `LAOR_INFINITE_V2_NATIVE`)는 한 회차 예산을 절반으로 나눠 **평단가 매수**와 **큰수 매수** 두 절반으로 운용한다. 큰수 매수의 현재 구현은 다음과 같다.

- 큰수 매수 지정가 = `전일 종가 × (1 + bigBuyPremiumRate)` (`strategyEngine.js:289`, `autoTradingStrategyEngine`)
- `bigBuyPremiumRate` 기본값 = `0.1 / splitCount` (`buyAlgorithm.js:resolveBigBuyPremiumRate`)

이 두 가지가 라오어 무한매수법의 "큰 수" 개념과 어긋난다. 라오어의 "큰 수" LOC는 (1) 내 **평단가**에 앵커되고, (2) 평단가보다 **충분히 높은 가격**이라 상승장에서도 거의 매일 체결된다. 현재 구현은 전일 종가에 앵커되고 기본 여유율이 40분할 기준 +0.25%에 불과해, 큰수 매수가 평단가 매수처럼 하락·보합일에만 체결되어 두 절반의 상호보완이 무너진다. 자세한 배경은 `proposal.md` 참고.

이전 change `2026-05-15-change-buy-algorithm`이 "정통 V2는 `+0.1/N`"이라는 출처 없는 전제로 도입한 것이며, 본 change는 그 전제를 라오어 원형에 맞게 정정한다.

## Goals / Non-Goals

**Goals:**
- 큰수 매수 지정가를 `평단가 × (1 + bigBuyPremiumRate)`로 변경. 평단가 매수와 같은 기준에 앵커.
- `bigBuyPremiumRate` 기본값을 분할 회차와 무관한 **고정 `0.1`(10%)** 로 변경.
- 사용자가 명시한 값을 그대로 쓰는 override 동작 유지.
- 백테스트 엔진(`strategyEngine.js`)의 일봉 평가와 단일가 평가(`evaluate`), 자동매매 엔진(`autoTradingStrategyEngine.js`)에 동일 적용.
- 알고리즘 설명 화면·입력 도움말·`README.md`·openspec baseline을 새 동작에 맞게 갱신.
- 영향받는 백엔드 테스트를 새 산식 기준으로 갱신.

**Non-Goals:**
- 매도 로직(목표 매도, 회차 소진 1/4 매도) 변경.
- carryover(이월) 정책, 사이클 재시작·복리, 분할회차 cap 변경.
- 첫 매수(보유 0) 흐름 변경 — 시가/현재가 단건 그대로.
- DB 스키마 변경·마이그레이션.
- 평단가 매수 쪽 동작 변경.

## Decisions

### D1. 큰수 매수 지정가 기준을 전일 종가 → 평단가로

큰수 매수 지정가 = `평단가 × (1 + bigBuyPremiumRate)`.

**채택 이유**: 라오어의 "큰 수" LOC는 평단가에 앵커된 값이다. 평단가 매수(`평단가 × 1`)와 큰수 매수(`평단가 × (1 + rate)`)가 같은 기준을 공유해야 "하락일=평단가 매수 / 상승·보합일=큰수 매수"의 상호보완이 성립한다. 전일 종가 앵커는 기준이 내 비용이 아니라 시장가라서 이 구조가 깨진다.

**대안**: 전일 종가 기준 유지하고 여유율만 키우기 — 기각. 앵커 자체가 라오어와 다르므로 여유율만으로는 정정되지 않는다.

### D2. 기본 여유율을 고정 `0.1`로

`resolveBigBuyPremiumRate`의 기본값 `0.1 / count` → `0.1`.

**채택 이유**: "큰 수"는 분할 회차가 아니라 목표 수익률대(약 10%) 수준의 큰 값이어야 상승장에서도 체결된다. 분할 회차가 많을수록 한 회차 *금액*은 이미 자동으로 작아지므로, 가격 상한까지 또 나누는 것은 이중 보수화이며 라오어에 없는 규칙이다.

**대안**: `0.1 / count` 유지 / 5% 고정 — 사용자 확인 결과 10% 고정 채택.

### D3. `big_buy_premium_rate` 컬럼·override 동작 유지

컬럼 의미("NULL이면 산식, 값이면 override")는 그대로. 산식만 D2로 바뀐다. 마이그레이션 불필요.

**기존 데이터 영향**: `big_buy_premium_rate`에 `0.1`이 명시 저장된 행은 그대로 override(10%)로 동작 — 새 기본값과 우연히 같다. NULL 행은 새 기본값(고정 10%)을 받는다. 별도 데이터 정정 없음.

### D4. 백테스트 일봉 체결 규칙은 그대로, 지정가 값만 교체

체결 규칙은 변경 없음: `low ≤ 큰수 지정가`이면 체결, 체결가 `min(open, 큰수 지정가)`. 지정가 계산식만 `prevClose × (1+rate)` → `평단가 × (1+rate)`.

**결과**: 큰수 지정가(평단가의 110%)는 보통 그날 시장가보다 위이므로 일봉 저가가 거의 항상 그 아래에 닿아 큰수 매수가 거의 매일 체결되고, 체결가는 대개 `min(open, 평단가×1.1) = open`이 된다. 이는 "거의 매일 매수"라는 라오어 의도와 일치한다. 전일 종가(`prevClose`) 입력은 큰수 매수 계산에서는 더 이상 쓰지 않는다.

### D5. 단일가 평가(`evaluate`)도 동일 적용

`strategyEngine.js`의 라이브 호환 단일가 평가 경로(`evaluate`)도 큰수 매수 상한을 `평단가 × (1+rate)`로 맞춘다. 두 평가 경로가 갈라지지 않도록 한다.

### D6. 영향받는 테스트 갱신

`prevClose` 기준 기대값(예: `orderPrice === previousClose × (1+rate)`, "큰수 지정가" 관련 HOLD/BUY 분기)을 쓰는 기존 테스트를 평단가 기준으로 수정하고, 평단가 기준 체결을 검증하는 케이스를 추가한다.

## Risks / Trade-offs

- **[RUNNING 자동매매 전략 행위 변경]** → 큰수 매수 상한이 넓어져 체결 빈도·매수 단가가 달라진다(상승장에서 더 자주 매수). 운영 공지 필요. → `README.md`와 자동매매 화면 설명으로 변경 사실을 노출.
- **[기존 백테스트 결과와 비교 불가]** → 같은 입력이라도 큰수 매수 산식이 달라 이전 `backtest_runs` 결과와 직접 비교할 수 없다. → 알고리즘 식별자(`LAOR_INFINITE_V2_NATIVE`)는 유지되므로 사용자는 동일 알고리즘명 아래 결과 차이를 인지. baseline 문서에 산식 변경 명시.
- **[기존 override 값 `0.1`의 모호성]** → 과거 자동 산식이 `0.1`을 만들 수 없었으므로(항상 `0.1/N`) `0.1` 저장 행은 사용자 override가 명백하다. 데이터 해석 충돌 없음.
- **[큰수 매수가 거의 매일 체결되어 회차 소진이 빨라짐]** → 의도된 동작(라오어는 매일 매수). 회차 소진 시 1/4 매도·사이클 재시작 로직이 이미 이를 처리한다.
