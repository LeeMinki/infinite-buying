## Why

현재 첫 화면은 상단 메뉴와 중복되는 이동 카드가 중심이라 실제 운용 현황판처럼 느껴지지 않는다. 또한 대시보드 이동이 브라우저 history back에 의존해 다른 화면으로 이동할 수 있고, 백테스트는 라오어 무한매수법 중심 구현과 랭킹 전략의 한계가 화면과 문서에서 충분히 구분되지 않는다.

## What Changes

- 대시보드 버튼은 사용자가 어느 화면에 있든 항상 대시보드로 직접 이동하도록 수정한다.
- 대시보드를 단순 런처가 아니라 계좌·손익·전략·주문·오류·운영 상태를 보여주는 운용 현황판으로 재구성한다.
- 매수가능금액, 총 평가금액, 오늘 손익, 오늘 수익률, 계산 가능한 기간별 수익률/수익 금액을 표시한다.
- 장기 계좌 스냅샷 저장 구조는 만들지 않고, 현재 확보 가능한 계좌·주문·전략 데이터로 계산 가능한 범위만 표시한다.
- 설정 완료 사용자에게 체크리스트를 크게 노출하지 않고, 설정 문제 또는 연결 확인이 필요한 경우에만 경고형 안내로 표시한다.
- 중앙의 KIS 설정/백테스트/자동매매 단순 이동 카드는 핵심 현황보다 낮은 우선순위로 내리거나 제거한다.
- 라오어 무한매수법, 한국 국장 상승률 랭킹, 미국장 상승률 랭킹 전략의 실행 상태·최근 판단·최근 주문·오류 상태를 구분해 보여준다.
- 서비스 이름과 부제를 현재 기능 범위에 맞게 검토하고, 라오어 단일 전략처럼 보이지 않는 전략 운용 도구 성격의 문구로 정리한다.
- 브라우저 탭에서 식별 가능한 파비콘을 추가한다.
- 백테스트는 라오어 중심 구현과 랭킹 전략 백테스트의 한계를 문서화하고, 정확한 백테스트와 근사 시뮬레이션을 구분하는 방향을 제안한다.

## Capabilities

### New Capabilities

- `app-branding`: 서비스 이름, 부제, 파비콘 등 앱 브랜딩 표시 기준.
- `backtest-direction`: 라오어 백테스트와 랭킹 전략 시뮬레이션/백테스트 방향성 및 한계.

### Modified Capabilities

- `dashboard`: 대시보드 이동, 운용 현황판, 체크리스트 노출, 계좌·손익·전략·주문·오류·운영 상태 요구사항 변경.
- `frontend-screens`: 상단 네비게이션과 주요 화면 표시 문구/진입 우선순위 조정.

## Impact

- Frontend: `App.jsx` 라우팅, `DashboardPage`, 상단 네비게이션, 브랜딩 텍스트, favicon asset, dashboard 스타일.
- Backend/API: 대시보드 표시용 계좌 요약, 전략별 상태, 최근 주문/판단/오류 조회 API 또는 기존 overview API 조합.
- Documentation/OpenSpec: dashboard, frontend-screens, app-branding, backtest-direction 명세.
- Out of scope: 장기 계좌 스냅샷 테이블, 과거 랭킹 스냅샷 저장 테이블, 국장/미국장 랭킹 전략의 정확한 과거 백테스트 구현.
