## Context

한국장 상승률 랭킹 전략은 현재 오전 09:10, 선택 시 점심 11:30 진입 구간에서 상승률 랭킹 후보를 고르고, 보유 중 30초 평가 tick에서 현재가가 목표 수익률 또는 손절 기준에 닿았는지 확인해 전량 매도한다. 미국장 상승률 랭킹 전략은 ET 10:00~16:00 동안 30초 평가 tick으로 상승률 후보를 사고, 익절 후 재진입하거나 손절·강제 청산 시 당일 매수를 중단한다.

실거래 분봉 복기 결과, 목표 수익 가격을 장중에 지나쳤는데 폴링 평가 시점에는 이미 내려와 익절을 놓친 사례가 있었다. 또한 손실 거래 대부분은 매수 직후 보유 중 최대 상승률이 거의 없었고, 진입 직후 흐름이 무너졌는데도 고정 손절선까지 기다린 뒤 매도됐다. 따라서 이번 change는 수익/손실 퍼센트 숫자만 바꾸지 않고, 주문 실행 방식과 진입 실패 판정, 후보 필터, 분봉 리플레이 검증을 함께 다룬다.

## Goals / Non-Goals

**Goals:**

- 한국장·미국장 랭킹 전략에서 매수 체결 확인 후 목표 수익 지정가 매도 주문을 즉시 제출한다.
- 목표가 주문, 손절 주문, 진입 실패 주문을 서로 구분해 중복 주문 없이 추적한다.
- 보유 중 분봉 흐름이 시가·VWAP·고점·거래량 기준으로 빠르게 무너지면 "진입 실패"로 판단해 전량 매도한다.
- 랭킹 후보 선정 시 매수가능금액, 고점 이탈, 거래량 감소, 과열, 위험 종목 조건을 더 보수적으로 적용한다.
- KIS 과거 분봉으로 실제 거래를 복기하는 리플레이 기능을 추가해 MFE/MAE와 파라미터 변경 결과를 확인한다.
- 실주문 안전 원칙과 사용자별 데이터 격리를 유지한다.

**Non-Goals:**

- 라오어 무한매수법 알고리즘 변경.
- 일봉 기반 백테스트를 한국장·미국장 랭킹 전략에 억지로 적용.
- 실시간 웹소켓 시세 도입.
- 완전한 체결 시뮬레이터 구현.
- 리플레이 결과로 자동 파라미터를 바꾸는 최적화 기능.
- KIS 주문 API 외 다른 브로커 또는 데이터 공급자 도입.

## Decisions

### 1. 목표 수익은 폴링 감지가 아니라 선주문으로 잡는다

현재 구조는 평가 tick이 목표 수익 도달을 확인한 뒤 매도 주문을 만든다. 30초 주기라도 급등락 종목에서는 1분 안에 목표가를 찍고 되돌리는 경우가 있어 수익 기회를 놓칠 수 있다.

결정: 매수 주문이 실제 체결로 확인되면, 평균 체결가 기준 목표 수익 지정가 매도 주문을 즉시 제출한다. 한국장은 시장가 매수 후 체결 확인 시 목표가 지정가 매도를 만들고, 미국장은 현재 KIS 해외 주문 경로에서 허용되는 지정가 매도 방식으로 목표가 주문을 만든다. 목표가 주문이 이미 있으면 새 목표가 주문을 만들지 않는다.

대안: 스케줄러 주기를 5초로 낮춘다. KIS rate limit과 서버 부하가 커지고 그래도 순간 고가를 놓칠 수 있어 기각한다.

### 2. 주문 상태는 접수와 체결을 분리한다

KIS 주문 접수는 체결이 아니다. 기존 안전 원칙을 유지해, 목표가 주문도 `ACCEPTED`만으로 청산 확정하지 않는다. 주문 상태 refresh 또는 체결조회로 체결 수량과 평균 체결가가 확인되어야 주문 이력의 실제 매도가와 손익이 확정된다.

목표가 주문이 미체결인 상태에서 손절 또는 진입 실패가 발생하면 기존 목표가 주문을 취소하거나, 취소가 불확실하면 신규 매도 주문을 차단하고 안전한 상태를 기록해야 한다. 구현 단계에서는 KIS 취소 가능 여부와 기존 취소 경로를 확인해 다음 우선순위를 적용한다.

1. 기존 목표가 미체결 주문 취소.
2. 취소 성공 후 손절/진입 실패 매도 주문 제출.
3. 취소 실패 또는 취소 상태 불명확이면 신규 주문을 만들지 않고 경고 로그를 남김.

### 3. 진입 실패 판정은 고정 손절보다 빠른 방어 장치로 둔다

진입 실패 판정은 손절률을 무조건 낮추는 기능이 아니다. 급등주 특성상 정상적인 흔들림은 허용하되, 매수 직후 모멘텀 조건이 무너졌을 때 고정 손절선까지 기다리지 않기 위한 장치다.

판정 입력은 최근 분봉, 매수 시각, 현재가, 평균가, VWAP, 당일 시가, 최근 고점, 거래량 추세다. 기본 조건은 다음 방향으로 설계한다.

- 현재가가 VWAP 아래로 내려가고 회복하지 못함.
- 현재가가 당일 시가 아래로 내려감.
- 최근 고점 대비 일정 비율 이상 밀림.
- 최근 N봉 거래량이 직전 구간 대비 크게 줄어 추세가 꺼짐.
- 거래량을 동반한 장대 음봉 발생.

한국장·미국장 모두 같은 개념을 쓰되, 시장별 기본값은 다르게 둘 수 있다.

### 4. 후보 필터는 "못 살 종목"과 "이미 꺾인 종목"을 먼저 제외한다

랭킹 후보 선정 단계에서 매수가능금액으로 1주도 살 수 없는 종목을 제외하는 기존 보강을 유지하고, 다음 후보로 넘어간다. 여기에 다음 조건을 추가한다.

- 고점 돌파 실패 또는 고점 대비 과도한 이탈.
- 거래량 감소.
- 급등률 과열.
- 한국장은 확인 가능한 경우 우선주, 관리/투자경고/거래정지 위험 종목 제외.
- 미국장은 저가·저거래량 기준을 더 보수적으로 적용하고, 가능하면 거래대금 기준도 사용.

단, 필터가 너무 강해 매수 기회를 모두 없애는 위험이 있으므로 거절 사유를 기록하고 리플레이로 검증 가능하게 한다.

### 5. 분봉 리플레이는 백테스트가 아니라 거래 복기다

한국장·미국장 랭킹 전략은 특정 시각의 상승률 랭킹, 분봉 흐름, 주문 체결 여부가 핵심이다. 과거 모든 시점의 랭킹 스냅샷을 저장하지 않은 상태에서 정확한 백테스트를 만들 수 없다.

결정: 이번 change는 "거래 복기/리플레이"를 추가한다. 대상은 실제 주문 이력 또는 선택된 거래 기록이다. KIS 과거 분봉으로 매수~매도 구간과 매도 후 일정 구간을 조회하고 다음 값을 계산한다.

- MFE: 매수 후 최대 상승률.
- MAE: 매수 후 최대 하락률.
- 목표 수익 도달 시각.
- 손절 도달 시각.
- 진입 실패 조건 도달 시각.
- 매도 후 30분/60분/장마감까지의 최대 상승·하락.
- 대체 파라미터 결과 비교.

리플레이는 사용자가 버튼을 눌렀을 때 제한된 기간과 거래 수만 조회한다. 화면 렌더링마다 KIS를 호출하지 않는다.

### 6. 저장은 최소화하고 캐시는 선택적으로 둔다

리플레이는 우선 read-only 계산으로 시작한다. 같은 거래를 여러 번 분석할 때 KIS 호출이 과도해지면 `rank_replay_results` 같은 캐시 테이블을 추가할 수 있다. 캐시를 추가하더라도 주문 원장과 체결 원장을 수정하지 않는다.

## Risks / Trade-offs

- **[목표가 주문과 손절 주문 충돌]** → 목표가 미체결 주문이 있으면 손절/진입 실패 주문 전에 취소를 시도하고, 취소 상태가 불확실하면 신규 매도를 차단한다.
- **[목표가 주문이 체결됐는데 앱이 늦게 아는 문제]** → 평가 tick과 수동 refresh에서 체결조회를 수행하고, 접수 상태만으로 포지션을 지우지 않는다.
- **[진입 실패 판정이 너무 민감해 정상 반등 종목을 조기 매도]** → 기본값은 보수적으로 시작하고, 리플레이로 조건별 결과를 확인한 뒤 조정한다.
- **[KIS 과거 분봉 호출량 증가]** → 리플레이는 사용자 명시 실행, 기간·거래 수 제한, 동일 거래 캐시로 제어한다.
- **[미국 과거 분봉 제공 범위 제한]** → 제공 범위를 초과하면 리플레이 불가 상태를 명확히 표시한다.
- **[한국장 우선주/투자경고 정보 부족]** → KIS에서 안정적으로 조회 가능한 필드만 적용하고, 불확실한 필터는 적용하지 않는다.

## Migration Plan

1. 기존 주문·체결 테이블을 확인해 목표가 주문과 손절 주문을 구분할 필드가 충분한지 점검한다.
2. 부족하면 최소 ALTER 또는 새 보조 테이블을 추가한다.
3. 목표가 주문 생성은 실주문 OFF에서는 기록만 저장하고, 실주문 ON에서만 KIS 주문을 보낸다.
4. 진입 실패 판정은 처음에는 판단 로그와 수동 evaluate에서 검증한 뒤 스케줄러 실주문 경로에 적용한다.
5. 리플레이 API와 UI는 주문 실행 경로와 분리해 배포한다.

Rollback은 목표가 주문 자동 생성과 진입 실패 매도를 feature flag 또는 설정값으로 끄는 방식이 가장 안전하다. DB 스키마가 추가되더라도 기존 주문 원장은 그대로 둔다.

## Open Questions

- 한국장 목표가 매도는 KIS 국내 주문에서 어떤 주문구분을 사용할지 최종 확인이 필요하다.
- 미국장 목표가 매도 주문이 장중 일반 지정가로 충분한지, LOC 등 별도 주문 타입이 더 적절한지 확인이 필요하다.
- 진입 실패 기본값을 전략 설정으로 노출할지, 내부 기본값으로 둘지 결정이 필요하다.
- 리플레이 결과를 DB에 캐시할지, 첫 구현에서는 응답 계산만 할지 구현 시 결정한다.
