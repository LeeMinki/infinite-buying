## Context

자동매매 도메인은 라오어 무한매수법, 한국 국장 상승률 랭킹, 미국장 상승률 랭킹 전략을 별도 테이블과 화면 패널로 운용한다. 현재 한국장·미국장 랭킹 화면은 기록 테이블 구성이 서로 다르고, 전략 삭제가 실제 전략 행 삭제로 이어져 연결된 이력이 함께 사라질 수 있다. 메인 화면은 예전 라오어 중심의 사이드 패널이 남아 있어 백테스트·자동매매·KIS 설정으로 바로 이동하려는 현재 사용 흐름과 맞지 않는다.

## Goals / Non-Goals

**Goals:**
- 한국장·미국장 랭킹 전략 삭제 시 주문·판단·진입/매매 이력을 보존한다.
- 자동매매 화면의 기본 탭 순서를 한국장 랭킹, 미국장 랭킹, 라오어 순으로 바꾼다.
- 메인 화면을 주요 기능 진입 카드 중심으로 재구성한다.
- 한국장·미국장 랭킹 상세 화면은 주문 이력과 판단 로그만 기본 기록 섹션으로 노출한다.
- 주문 이력은 매수와 매도를 묶은 왕복 거래 단위로 보여준다.
- 판단 로그는 10개를 먼저 보여주고 더보기로 추가 표시한다.

**Non-Goals:**
- 랭킹 전략의 매수·매도 알고리즘을 변경하지 않는다.
- 라오어 무한매수법의 상세 UI와 데이터 모델은 이번 변경에서 재설계하지 않는다.
- 삭제된 전략의 복구 기능은 구현하지 않는다.
- KIS API 연동 방식, 주문 실행 방식, 스케줄러 주기는 변경하지 않는다.

## Decisions

1. **전략 삭제는 soft delete로 처리한다.**
   - 한국장 `kr_rank_strategies`, 미국장 `us_rank_strategies`에 `deleted_at` 또는 동등한 삭제 상태를 추가한다.
   - 삭제 API는 전략 행을 물리 삭제하지 않고 실행 대상과 기본 목록에서 제외한다.
   - 주문·판단·진입/매매 테이블은 기존 `strategy_id`를 유지한다.
   - 이유: 실제 매매 이력은 사후 검토와 손익 복기에 필요하며, `ON DELETE CASCADE` 구조에서 물리 삭제하면 원장을 잃는다.

2. **랭킹 전략 주문 이력은 read model로 구성한다.**
   - 한국장은 `kr_rank_entries`와 `kr_rank_orders`를, 미국장은 `us_rank_trades`와 `us_rank_orders`를 조합해 왕복 거래 행을 만든다.
   - API 응답은 시장별 내부 구조 차이를 숨기고 `buyTime`, `symbolName`, `buyPrice`, `sellTime`, `sellPrice`, `sellReason`, `profitRate` 형태로 맞춘다.
   - 이유: 화면은 사용자가 이해하는 매매 단위가 필요하고, 내부 주문 row를 그대로 보여주면 매수·매도가 분리되어 손익 파악이 어렵다.

3. **진입 기록/매매 사이클 테이블은 기본 화면에서 제거하되 데이터는 보존한다.**
   - 한국장의 진입 기록과 미국장의 매매 사이클은 주문 이력 계산에 사용하거나 필요 시 API 내부에서 유지한다.
   - 이유: 사용자가 기본적으로 확인하려는 정보는 언제 사고 팔았는지, 왜 팔았는지, 손익이 얼마인지다.

4. **판단 로그는 클라이언트 10개 단위 더보기로 시작한다.**
   - 기존 API가 limit/offset을 지원하면 그대로 사용하고, 부족하면 서버 목록 API에 `limit`, `offset` 또는 `cursor`를 추가한다.
   - 이유: 판단 로그는 스케줄러로 빠르게 늘어나며, 첫 화면에서는 최근 판단만 보여주는 것이 읽기 쉽다.

5. **홈 화면은 기능 진입 대시보드로 바꾼다.**
   - 왼쪽 사이드의 시작 가이드·공통 전략 초안은 제거한다.
   - 백테스트, 자동매매, KIS 설정을 첫 화면의 주요 액션으로 제공하고, 자동매매 카드에서는 한국장·미국장 랭킹 전략도 명확히 드러낸다.
   - 이유: 현재 앱의 핵심 사용 흐름은 전략 초안 작성이 아니라 KIS 설정 후 백테스트 또는 자동매매로 진입하는 것이다.

## Risks / Trade-offs

- **기존 외래키가 `ON DELETE CASCADE`라 soft delete 전환 시 목록 쿼리 누락 위험** → 모든 전략 목록과 스케줄러 대상 쿼리에 `deleted_at IS NULL` 조건을 추가하고 테스트한다.
- **왕복 거래 read model이 시장별 테이블 차이로 복잡해질 수 있음** → 한국장·미국장 각각 repository helper를 두되 프론트 응답 형식은 동일하게 맞춘다.
- **삭제된 전략 이력을 어디서 다시 볼지 모호할 수 있음** → 이번 변경은 이력 보존을 보장하고, 삭제된 전략 목록/복구 UI는 후속으로 분리한다.
- **홈 화면 개편이 기존 라오어 사용자 흐름을 숨길 수 있음** → 자동매매 카드 안에 라오어도 함께 진입 가능하게 두되, 화면 우선순위만 한국장·미국장 랭킹 중심으로 조정한다.
