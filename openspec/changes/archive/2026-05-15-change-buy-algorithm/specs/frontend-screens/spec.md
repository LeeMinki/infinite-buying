## ADDED Requirements

### Requirement: 큰수 매수 여유율 입력의 산식 안내

전략 초안/생성 폼의 `큰수 매수 여유율` 입력 박스에는 다음 안내가 표시되어야 한다:
- placeholder 또는 helper text에 "비워두면 0.1 / 분할회차 자동 계산"
- 입력값이 비어있는 상태에서 분할회차가 결정되면 계산된 값(예: 40분할이면 `0.0025 (≈0.25%)`)을 미리보기로 표시

#### Scenario: 사용자가 분할회차 40 입력 후 여유율은 비워둠
- **WHEN** `splitCount=40`을 입력하고 `bigBuyPremiumRate` 입력은 비어 있음
- **THEN** 폼은 "자동: 0.0025 (≈0.25%)" 같은 미리보기를 표시해야 한다

#### Scenario: 사용자가 직접 값 입력
- **WHEN** 사용자가 `bigBuyPremiumRate=0.05`를 입력
- **THEN** 폼은 자동 계산 미리보기 대신 사용자 입력 0.05를 적용 값으로 표시해야 한다

### Requirement: 분할회차 자동 cap UI

전략 생성 폼의 분할회차 입력 박스는 다음 산식으로 최대값을 자동 계산해 안내하고, 그 이상의 값은 입력 자체가 차단되어야 한다.

```
maxSplitCount = floor(totalBudget / (referencePrice × 2))
```

`referencePrice`는 선택된 종목의 KIS 현재가.

#### Scenario: 종목과 예산이 결정되면 cap 표시
- **WHEN** 사용자가 종목을 선택하고 총예산을 입력
- **THEN** 분할회차 입력 박스에 "최대 N분할" 안내와 max=N 속성이 적용되어야 한다

#### Scenario: cap을 초과하는 입력
- **WHEN** 사용자가 cap을 초과하는 분할회차를 입력
- **THEN** 입력값이 자동으로 cap으로 클램프되거나 입력이 무시되어야 한다

#### Scenario: 종목 또는 예산 변경 시 재계산
- **WHEN** 사용자가 종목 또는 총예산을 바꿈
- **THEN** 분할회차 cap이 즉시 재계산되어 UI에 반영되어야 한다

### Requirement: "1주 단위 매수" 안내

자동매매 전략 생성/상세 화면에 다음 안내가 노출되어야 한다.

> 이 시스템은 KIS Open API 기준으로 **1주 단위 매수**만 지원합니다. 회차 예산이 1주 가격보다 작으면 매수가 다음 사이클로 이월(carryover)됩니다.

#### Scenario: 전략 생성 폼
- **WHEN** 사용자가 자동매매 전략 생성 폼을 연다
- **THEN** 폼 상단 또는 헤더에 1주 단위 매수 안내가 노출되어야 한다

#### Scenario: 자동매매 상세
- **WHEN** 사용자가 자동매매 전략 상세를 연다
- **THEN** 알고리즘 가이드 패널 또는 보조 영역에 1주 단위 매수 안내가 노출되어야 한다

### Requirement: 알고리즘 가이드(LaorStrategyGuide) 본문 갱신

`LaorStrategyGuide` 패널은 다음을 반영해야 한다.
1. 큰수 매수 상한 산식이 `전일종가 × (1 + 0.1/분할회차)`이고 사용자가 override 가능.
2. 매수 평가가 한 사이클에서 두 절반(`평단가 매수`, `큰수 매수`)의 지정가 주문 2건을 KIS에 동시 접수.
3. 두 주문 중 일부만 체결될 수 있고 미체결은 다음 평가 직전 자동 취소.
4. 1주 단위 매수만 가능. 1주 미만은 carryover로 이월.

#### Scenario: 사용자가 알고리즘 가이드를 펼침
- **WHEN** 사용자가 자동매매 상세에서 알고리즘 설명 패널을 펼친다
- **THEN** 본문은 위 4개 요점을 모두 설명해야 한다

### Requirement: 주문 목록의 절반 종류 칩

자동매매 상세 화면의 주문 목록은 각 주문 행에 절반 종류 칩(`평단가 매수` / `큰수 매수` / `첫 매수` / `매도`)을 표시해야 한다.

#### Scenario: 한 사이클에 두 주문
- **WHEN** 한 평가에서 `AVG`/`BIG` 두 주문이 만들어짐
- **THEN** 주문 목록에 두 행이 표시되고 각각 `평단가 매수` / `큰수 매수` 칩이 보여야 한다

### Requirement: 결정 로그의 주문 그룹화

자동매매 상세의 결정 로그 영역은 같은 `decision_log_id`로 연결된 주문들을 한 결정 단위로 묶어 표시해야 한다.

#### Scenario: 두 주문 그룹화
- **WHEN** 한 결정이 AVG/BIG 두 주문을 생성
- **THEN** UI에 그 결정 카드 안에 두 주문 행이 함께 보여야 한다

### Requirement: 백테스트 결과 화면의 알고리즘 버전 표시

백테스트 결과 화면은 결과가 본 change 도입 후의 알고리즘으로 계산되었음을 식별할 수 있는 라벨/배지를 표시해야 한다.

#### Scenario: 결과 카드
- **WHEN** 사용자가 백테스트 결과를 연다
- **THEN** 알고리즘 버전 라벨(예: `LAOR_INFINITE_V2_NATIVE`)이 표시되어야 한다
