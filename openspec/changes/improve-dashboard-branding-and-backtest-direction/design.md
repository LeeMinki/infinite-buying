## Context

현재 로그인 후 첫 화면은 상단 메뉴가 있음에도 중앙에 KIS 설정, 백테스트, 자동매매 이동 카드가 크게 배치되어 있다. 이 구조는 기능 진입에는 도움이 되지만, 실제 자동매매 운용자가 기대하는 계좌 상태, 손익, 실행 중 전략, 최근 주문/오류 확인에는 약하다.

또한 `App.jsx`의 대시보드 이동은 `strategies` view로 이동할 때 browser history back을 사용하는 경로가 있어, KIS 설정이나 다른 하위 화면에서 대시보드 버튼을 눌렀을 때 사용자가 기대하지 않은 이전 화면으로 갈 수 있다.

백테스트는 현재 라오어 무한매수법의 일봉 기반 계산에 맞춰져 있다. 한국/미국 랭킹 전략은 특정 시각의 상승률 랭킹, 현재가, 거래량, 장중 익절/손절에 의존하므로 기존 일봉 백테스트와 동일하게 재현하기 어렵다.

## Goals / Non-Goals

**Goals:**

- 대시보드 버튼을 항상 대시보드로 직접 이동시키는 라우팅으로 고친다.
- 대시보드를 계좌·손익·전략·주문·오류·운영 상태 중심의 운용 현황판으로 재구성한다.
- 체크리스트와 단순 이동 버튼의 노출 우선순위를 낮춘다.
- 라오어, 한국 랭킹, 미국 랭킹 전략 상태를 분리해서 보여준다.
- 앱 이름/부제와 파비콘을 전략 운용 도구에 맞게 정리한다.
- 랭킹 전략 백테스트의 정확도 한계와 향후 방향을 문서와 UI 문구에 명확히 반영한다.

**Non-Goals:**

- 장기 계좌 스냅샷 저장 테이블 추가.
- 과거 랭킹 스냅샷 수집/저장 테이블 추가.
- 국장/미국장 랭킹 전략의 정확한 과거 백테스트 구현.
- KIS 주문/체결 로직 변경.
- 자동매매 전략 알고리즘 변경.

## Decisions

### 1. 대시보드 이동은 history back을 사용하지 않는다

대시보드 버튼은 `setViewState('strategies')`와 `history.pushState/replaceState` 정리를 통해 직접 대시보드 view로 이동한다. 이전 화면으로 돌아가는 동작은 브라우저 뒤로가기 버튼에만 맡긴다.

대안으로 현재처럼 `window.history.back()`을 유지할 수 있지만, 사용자의 의도와 browser history stack이 항상 일치하지 않는다. 대시보드 메뉴는 명령형 이동이므로 직접 이동이 맞다.

### 2. 대시보드는 런처가 아니라 현황판으로 둔다

중앙의 큰 이동 카드는 제거하거나 보조 영역으로 낮추고, 상단에는 계좌 요약과 운용 상태를 둔다.

표시 우선순위:

1. 계좌 상태: 매수가능금액, 총 평가금액, 오늘 손익, 오늘 수익률.
2. 운영 상태: KIS 연결, 계좌 조회, 장 운영 상태, 실주문 설정.
3. 전략 상태: 라오어, 한국 랭킹, 미국 랭킹의 실행/정지/오류, 최근 판단, 최근 주문.
4. 문제 상황: 최근 오류, 주문하지 않은 사유, KIS 연결 필요.
5. 보조 액션: 설정/백테스트/자동매매 화면 이동.

### 3. 기간별 수익률은 현재 확보 가능한 데이터만 사용한다

이번 change에서는 장기 계좌 스냅샷 저장 구조를 만들지 않는다. 따라서 7일/30일 같은 기간별 수익률은 기존 주문/체결/전략 기록 또는 현재 계좌 조회로 계산 가능한 경우에만 표시한다. 기준 데이터가 없으면 `데이터 부족`으로 표시한다.

무리하게 부정확한 수익률을 계산하면 대시보드 신뢰도가 떨어진다. 정확한 기간 손익은 별도 change에서 계좌 스냅샷 저장을 설계한 뒤 확장한다.

### 4. 체크리스트는 온보딩/경고 상황에서만 노출한다

KIS 설정, 계좌 조회, 전략 생성 등 필수 설정이 완료된 사용자는 체크리스트를 기본으로 보지 않는다. 설정 누락이나 연결 실패가 있을 때만 경고형 안내로 표시하고, 모든 설정이 완료된 경우에는 접힌 보조 영역 또는 숨김 상태로 둔다.

### 5. 전략별 상태는 한 화면에서 구분한다

라오어, 한국 랭킹, 미국 랭킹은 서로 다른 엔진과 기록을 가진다. 대시보드에서는 하나의 `자동매매 실행 중` 숫자만 보여주지 않고, 전략 종류별 카드 또는 표로 다음 정보를 나눈다.

- 실행 상태.
- 최근 판단.
- 최근 주문/체결.
- 최근 오류 또는 주문하지 않은 사유.
- 보유 종목 또는 선택 종목.

### 6. 랭킹 전략은 백테스트와 시뮬레이션을 구분한다

라오어는 일봉 close 기준 백테스트가 가능하다. 반면 랭킹 전략은 특정 시각의 상승률 순위와 장중 체결/익절/손절에 의존한다. 과거 랭킹 스냅샷이 없으면 정확한 백테스트가 아니라 가격 데이터 기반 근사 시뮬레이션에 가깝다.

이번 change는 정확한 구현을 하지 않고 문서와 UI에서 이 차이를 정리한다. 이후 별도 change에서 랭킹 스냅샷 저장 또는 리플레이 시뮬레이션을 설계한다.

## Risks / Trade-offs

- [Risk] KIS 계좌 조회 API 실패 시 대시보드 핵심 값이 비어 보일 수 있다. → 연결 상태와 실패 사유를 별도 운영 상태로 표시하고, 기존 자동매매 화면 이동을 제공한다.
- [Risk] 기간별 수익률을 제한적으로 표시하면 사용자가 기능 부족으로 느낄 수 있다. → 데이터 부족 이유와 필요한 다음 단계(계좌 스냅샷 저장)를 명확히 표시한다.
- [Risk] 기존 메인 액션 카드 제거로 신규 사용자의 진입성이 낮아질 수 있다. → 설정 문제가 있을 때만 체크리스트/보조 액션을 노출한다.
- [Risk] 브랜딩 문구 변경이 사용자에게 낯설 수 있다. → 서비스명은 급격히 바꾸기보다 부제부터 전략 운용 도구 성격으로 정리한다.
